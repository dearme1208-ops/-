# 工程表アプリ：外部AIによる案件・ToDoの進捗登録 仕様書

この文書は、別のAI（Claude など）に「工程表」アプリの**案件**と**ToDo**の進捗を登録してもらうための仕様です。
あなた（AI）はこの文書を読んだうえで、利用者から渡される「現状のスナップショット（JSON）」を読み、
進捗の変化を **「進捗の更新（JSON）」** として書き出してください。利用者がそれをアプリに取り込みます。

---

## 1. 前提（必ず理解しておくこと）

- このアプリは**ブラウザの中だけで動く**アプリです（サーバー・APIはありません）。データは利用者の端末内にだけあります。
- そのため、あなたがアプリを直接書き換えることはできません。やり取りは次の往復です。
  1. 利用者がアプリの「🤖 AIと進捗をやり取り」→「現状を書き出す」で **スナップショット（JSON）** を作り、あなたに渡す
  2. あなたが **進捗の更新（JSON）** を作って返す
  3. 利用者が「進捗の更新を取り込む」に貼り付け（またはファイルを選び）、**確認画面で内容を見てから**反映する
- 取り込みは**書かれた操作だけ**を行います。書かれていない案件・ToDo・項目には一切触れません。
  （同じ画面の「CSV取り込み」は全件同期型で挙動が違います。AIからの進捗登録には使わないでください。→ 7章）
- 反映後は利用者が「元に戻す」で取り消せます。
- **削除はできません。** 不要になったものは利用者が手で消します。

## 2. データの考え方

### 2.1 案件（project）
- 1件の仕事。`title`（件名）, `category`（業務区分・大項目）, `workName`（詳細作業名）, `dueDate`（期日, 必須）を持つ。
- 任意で `groupName`（グループ名）, `tag`（対応状況）を持つ。
- **段階（stage）** に分けて進捗を管理する。段階は順番つきのリストで、次の2種類がある。
  - 通常の段階：`completed`（true/false）で完了を表す
  - 件数で進める段階：`targetCount`（目標件数）と `completedCount`（これまでの件数）を持ち、
    `completedCount >= targetCount` になると完了扱い
- 案件の**進捗率** = 各段階の進み（通常は0か1、件数型は completedCount/targetCount）の平均。
- 段階の**完了日時**は記録され、「何番目に終わったか」「このペースだといつ終わるか」の予測に使われます。
  **実際に終わった日を `completedDate` で必ず伝えてください**（省略すると取り込んだ時刻になります）。

### 2.2 ToDo（todo）
- リスト（`list`。例「タスク」）に属する。`title`, `dueDate`（任意）, `startDate`（任意）, `tag`（対応状況）,
  `important`（重要）, `action`（次にすべき具体的な行動）, `notes`（メモ）を持つ。
- **サブタスク**を持てる（1段まで）。サブタスクは `title`, `completed`, `dueDate`, `tag` を持つ。
  サブタスクがあるToDoの進捗率 = 完了したサブタスク数 / サブタスク数。
- **繰り返しのToDo**（スナップショットで `recurring: true`）は、完了にすると「完了」にはならず、**次回の期日へ進みます**
  （その際サブタスクは未完了に戻ります）。
- ToDoが案件に反映されている場合、スナップショットの `projectId` にその案件のIDが入ります。

### 2.3 対応状況（tag）
- 「社内確認中」「客先確認中」「打ち合わせ」「対応中」「保留」などの短い言葉。選択肢はスナップショットの `tagOptions` にあります。
- **選択肢にある言葉を使ってください。** 無い言葉も登録はできますが、警告が出ます。
- 「客先確認中」「社内確認中」など**相手の返事待ち**の状況は、アプリ内で「相手待ち」として日数が数えられ、
  進捗の一覧で「停滞」とは別に扱われます。返事待ちになったら `tag` を変えてください。
- 対応状況を変えた日時と、期日を延ばした履歴（延期の回数）は**アプリが自動で記録**します。

### 2.4 日付
- 日付はすべて `YYYY-MM-DD`（例 `2026-10-03`）。日本時間の日付です。
- 今日の日付はスナップショットの `today` にあります。
- 未来の `completedDate` は取り込み時刻に丸められます。

## 3. スナップショット（アプリ → AI）

アプリの「現状を書き出す」で作られるJSONです。**未完了の**案件・ToDoだけが入ります（アーカイブ済みは除く）。

```json
{
  "format": "koutei-progress-snapshot",
  "version": 1,
  "exportedAt": "2026-10-03T06:00:00.000Z",
  "today": "2026-10-03",
  "tagOptions": ["社内確認中", "客先確認中", "打ち合わせ", "対応中", "保留"],
  "todoLists": ["タスク", "個人"],
  "projects": [
    {
      "id": "k3j9...",
      "title": "A社見積",
      "category": "営業",
      "workName": "見積",
      "dueDate": "2026-10-20",
      "tag": "対応中",
      "createdDate": "2026-09-20",
      "completed": false,
      "stages": [
        { "id": "s1...", "title": "ヒアリング", "completed": true, "completedDate": "2026-09-25" },
        { "id": "s2...", "title": "見積作成", "completed": false, "dueDate": "2026-10-10" },
        { "id": "s3...", "title": "部品手配", "completed": false, "targetCount": 10, "completedCount": 3 }
      ]
    }
  ],
  "todos": [
    {
      "id": "t1...",
      "list": "タスク",
      "title": "B社対応",
      "tag": "客先確認中",
      "dueDate": "2026-10-08",
      "important": false,
      "recurring": false,
      "completed": false,
      "notes": "前回の経緯…",
      "subtasks": [
        { "id": "t1a...", "title": "資料送付", "completed": true, "completedDate": "2026-10-01" },
        { "id": "t1b...", "title": "日程調整", "completed": false }
      ]
    }
  ]
}
```

値が無い項目はキーごと省略されます。

## 4. 進捗の更新（AI → アプリ）

### 4.1 全体の形

```json
{
  "format": "koutei-progress-update",
  "version": 1,
  "operations": [
    { "op": "updateStage", "projectId": "k3j9...", "stageId": "s2...", "completed": true, "completedDate": "2026-10-02" }
  ]
}
```

- `format` と `version` は必ずこの値にしてください（違うとファイル全体を受け付けません）。
- `operations` は上から順に処理されます。前の操作で追加したToDo・段階を、後の操作で名前で指定できます。
- 1つの操作が失敗しても（対象が見つからない等）、**その操作だけ**が飛ばされ、残りは反映できます。
  失敗した操作は確認画面に理由つきで表示されます。
- JSON以外の文章を混ぜないでください（コードブロック ```json … ``` で囲むのは構いません。アプリ側で外します）。

### 4.2 対象の指定（ID推奨）

| 対象 | IDで指定 | 名前で指定（IDが分からないとき） |
|---|---|---|
| 案件 | `projectId` | `projectTitle`（未完了の案件の件名と完全一致。同名が複数あると失敗） |
| 段階 | `stageId` | `stageTitle`（その案件の中で完全一致） |
| ToDo | `todoId` | `todoTitle`（未完了の親ToDoの件名と完全一致）＋必要なら `list` で絞る |
| サブタスク | `subtaskId` | `subtaskTitle`（そのToDoの中で完全一致） |

**スナップショットのIDを使うのが確実です。** 名前の表記ゆれ（全角/半角・空白）は一致しません。

### 4.3 操作の一覧

省略した項目は**変更されません**。`null` または `""` を指定すると、その項目を**消します**（消せる項目のみ）。

#### updateStage — 段階の進捗を更新する（いちばんよく使う）
| 項目 | 型 | 説明 |
|---|---|---|
| projectId / projectTitle | 文字列 | 対象の案件（必須） |
| stageId / stageTitle | 文字列 | 対象の段階（必須） |
| completed | true/false | 完了にする／未完了に戻す |
| completedDate | 日付 | 実際に終わった日（完了にするとき推奨） |
| completedCount | 数 | 件数で進める段階の、これまでの件数（目標に達すると自動で完了） |
| dueDate | 日付 / null | 段階の期日 |
| tag | 文字列 / null | 段階の対応状況 |

件数で進める段階に `completed: true` を指定すると、件数が目標件数になります。
通常の段階に `completedCount` を指定するとエラーです。

#### addStage — 案件に段階を足す
| 項目 | 型 | 説明 |
|---|---|---|
| projectId / projectTitle | 文字列 | 対象の案件（必須） |
| title | 文字列 | 段階名（必須。同じ案件に同名があると失敗） |
| dueDate | 日付 | 期日（任意） |
| targetCount | 数 | 件数で進める場合の目標件数（任意） |
| position | 数 | 何番目に入れるか（0始まり。省略で最後） |

#### updateProject — 案件そのものを更新する
| 項目 | 型 | 説明 |
|---|---|---|
| projectId / projectTitle | 文字列 | 対象の案件（必須） |
| dueDate | 日付 | 期日（消すことはできない）。延ばすと延期として記録される |
| tag | 文字列 / null | 案件の対応状況 |
| completed | true/false | 案件を完了にする／戻す（段階を全部終えても案件は自動では完了にならない） |
| completedDate | 日付 | 完了日 |

#### addProject — 案件を新しく作る
| 項目 | 型 | 説明 |
|---|---|---|
| title | 文字列 | 件名（必須） |
| category | 文字列 | 業務区分（必須。作業時間の集計の区分になる） |
| workName | 文字列 | 詳細作業名（省略時は件名） |
| dueDate | 日付 | 期日（必須） |
| groupName | 文字列 | グループ名（任意） |
| tag | 文字列 | 対応状況（任意） |
| stages | 配列 | `[{ "title": "...", "dueDate": "...", "targetCount": 10 }]`（任意） |

未完了の案件に同じ「件名＋詳細作業名」があると失敗します（重複防止）。既存の案件は `updateProject` / `addStage` で更新してください。

#### updateTodo — ToDoを更新する
| 項目 | 型 | 説明 |
|---|---|---|
| todoId / todoTitle (+ list) | 文字列 | 対象のToDo（必須） |
| completed | true/false | 完了にする／戻す（繰り返しのToDoは次回の期日へ進む） |
| completedDate | 日付 | 完了日 |
| dueDate | 日付 / null | 期日 |
| tag | 文字列 / null | 対応状況 |
| important | true/false | 重要 |
| action | 文字列 | 次にすべき具体的な行動（""で消す） |
| notes | 文字列 | メモを**置き換える**（""で消す。既存のメモを消してしまうので通常は使わない） |
| appendNotes | 文字列 | メモの末尾に `[今日の日付] 内容` の1行を**追記する**（経緯の記録はこちら） |

#### addTodo — ToDoを新しく作る
| 項目 | 型 | 説明 |
|---|---|---|
| list | 文字列 | リスト名（必須。無ければ新しく作られる） |
| title | 文字列 | 件名（必須。同じリストに未完了の同名があると失敗） |
| dueDate / startDate | 日付 | 期日・開始日（任意） |
| tag, important, action, notes | | 任意 |
| subtasks | 配列 | `[{ "title": "...", "dueDate": "...", "tag": "..." }]`（任意） |

#### updateSubtask — サブタスクを更新する
| 項目 | 型 | 説明 |
|---|---|---|
| todoId / todoTitle (+ list) | 文字列 | 親のToDo（必須） |
| subtaskId / subtaskTitle | 文字列 | 対象のサブタスク（必須） |
| completed, completedDate | | 完了／未完了・完了日 |
| dueDate, tag | | 期日・対応状況（null で消す） |

#### addSubtask — サブタスクを足す
| 項目 | 型 | 説明 |
|---|---|---|
| todoId / todoTitle (+ list) | 文字列 | 親のToDo（必須） |
| title | 文字列 | 件名（必須。未完了の同名があると失敗） |
| dueDate, tag | | 任意 |

### 4.4 できないこと
- 削除（案件・段階・ToDo・サブタスク）
- 段階・サブタスクの並べ替え、名前の変更
- 作業時間（実績）の登録 … 作業時間はアプリの「本日の作業」で計測したものだけが記録されます
- 添付（画像・メール・URL）、取引先、案件の見積もり時間の変更

## 5. 例

利用者「A社の見積は昨日出した。部品は7個そろった。B社は資料を送って、いまは先方の返事待ち。来週C社の提案があるのでToDoに入れて」

```json
{
  "format": "koutei-progress-update",
  "version": 1,
  "operations": [
    { "op": "updateStage", "projectId": "k3j9...", "stageId": "s2...", "completed": true, "completedDate": "2026-10-02" },
    { "op": "updateStage", "projectId": "k3j9...", "stageId": "s3...", "completedCount": 7 },
    { "op": "updateSubtask", "todoId": "t1...", "subtaskId": "t1a...", "completed": true, "completedDate": "2026-10-03" },
    { "op": "updateTodo", "todoId": "t1...", "tag": "客先確認中", "appendNotes": "資料送付済み。先方の返事待ち" },
    { "op": "addTodo", "list": "タスク", "title": "C社提案", "dueDate": "2026-10-09", "subtasks": [{ "title": "提案書の構成" }, { "title": "見積添付" }] }
  ]
}
```

## 6. AIへのお願い（品質のための約束）

1. **スナップショットにあるIDで指定する。** 名前での指定はIDが無い新規追加の直後だけにする。
2. **変わったことだけを書く。** 変わっていない項目は書かない（同じ値を書いても害はないが、確認画面が読みにくくなる）。
3. **完了には実際の日付を付ける**（`completedDate`）。進み具合の予測が正確になる。
4. 期日を延ばすのは本当に延びたときだけ（延期の回数として記録される）。
5. 経緯は `appendNotes` で追記する。`notes` での置き換えは既存のメモを消すので使わない。
6. 利用者の話から判断がつかないもの（どの段階のことか分からない等）は推測で書かず、利用者に確認する。
7. 返すときは、JSONの前後に「何をどう更新するか」を日本語で短く箇条書きにすると、利用者が確認画面と見比べやすい。
   JSON自体は1つのコードブロックにまとめる。

## 7. 参考：CSV取り込み（AIからの進捗登録には使わない）

アプリには案件・ToDoのCSV取り込みもありますが、別アプリとの**全件同期**用で、次の挙動があるため進捗登録には向きません。
- 案件CSV：ファイルに載っていない（CSV由来の）案件を**自動で完了にする**。段階の完了・件数・対応状況を取り込めない。
- ToDo CSV：載せなかった列（メモ等）が**空で上書き**される。`id` が一致しないと**重複して新規作成**される。
